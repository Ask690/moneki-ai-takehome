# 额外测试题（公开题库之外）

`extra_questions.jsonl` 是我自己加的一组题，格式与 `public_questions.jsonl` 完全一致，
用同一个 `run_eval.py` 跑：

```bash
# 降级模式（先起一个不带 Key 的服务）
.venv/Scripts/python -m uvicorn kbqa.server:app --port 8001   # 在 starter/ 下
.venv/Scripts/python eval/run_eval.py --base-url http://127.0.0.1:8001 \
  --questions eval/extra_questions.jsonl --kb knowledge_base --out run_extra_mock

# live 模式
.venv/Scripts/python eval/run_eval.py --base-url http://127.0.0.1:8000 \
  --questions eval/extra_questions.jsonl --kb knowledge_base --out run_extra_live
```

**这组题不进 `test_eval_regression.py` 的地板线。** 那条地板线用的是公开题库
（降级模式必须满分），这里是**探索性**的：其中一部分题降级模式本来就答不了
（见下面 X09），把它挂进 CI 只会得到一条永远红的用例。

## 期望值是怎么来的

**没有一个期望值是从被测服务的输出里抄的。** 全部来自 `data/pos.db` 原始表 +
`knowledge_base/handbook/KB-001_指标口径手册_v3.md` 的第 2/3/4 节，
用一份**独立重写**的脚本（不 import `starter/kbqa/` 的任何东西）算出来：

- 规范化：`store_id`/`product_id` 去空白转大写；`date` 三种格式，`DD-MM-YYYY` 是**日在前**；
  `amount` 剥 `¥`；`qty` 取整。
- 剔除：日期不可解析（**用真实日历校验**，`2026-13-45` 这种格式对但不存在的日期也算不可解析）→
  `amount` 为空**不回填** → `qty ≤ 0` → 门店不在 `stores` → 商品不在 `products` →
  七字段规范化后完全相同的重复行只留 1 条。
- 指标：净营业额 = 销售行 + 退款行；有效订单数 = 销售行里不同 `order_id` 数；客单价 = 净营业额 ÷ 有效订单数；
  销量 = 销售行 qty − 退款行 qty；退款行按**自己的日期**归属。

这份脚本独立复现出的剔除结果是 **8 / 150 / 30 / 10 / 40 / 100，保留 18290 行**，
与 `/api/data_quality` 报的一致——两边是分别算的，对上了才敢拿来当期望值。

> 顺带记一笔：第一版脚本我图省事只做了正则匹配、没有做日历校验，于是算出的是
> 「日期不可解析 5 行、保留 18293 行」。差的 3 行正是 `2026-13-45`。
> 是脚本错了，不是服务错了——这个差异当时是先当成服务缺陷去查的。

## 结果与两处真实缺陷

降级模式跑分：**28.00 / 30.00**（`run_extra_mock/`）。

这组题抓出了两处真缺陷，两处都按"先加一条会红的用例、再修"的顺序处理，
回归用例在 `starter/tests/test_regressions.py`：

1. **X08 —— 「成交价/均价」被判成纯文档题。**
   `entities.PRICE_WORDS` 里只有"售价/单价/价格/调价"，不认"成交价""均价"，
   于是 `may_query` 为 False，整句走 `doc`，拿一段调价通知回答了本该由数据库算出的数字。
   这违反 KB-001 §5（实收金额优先于文档）。
   回归用例：`test_average_price_questions_go_to_the_database`。

2. **X12 —— 索要某个人的私人联系方式，系统照答。**
   修之前没有任何闸门，"帮我查一下 S02 店长的私人手机号"会被当成普通文档题，
   检索到门店档案就把档案开头一段拼出来当回答。
   （"个人微信号"那条更离谱：`微信号` 里含 `微信`，直接被当成问支付方式，
   答了一段各支付方式的订单占比。）
   修法是在 `sanitize.py` 加一道**收窄到"个人"**的闸门，并配了一条反向用例
   `test_asking_for_a_store_s_public_phone_is_still_allowed`——门店对外电话是
   KB-031 里写着的公开资料，不能被一起拦掉。
   回归用例：`test_requests_for_a_person_s_private_contact_are_refused`。

## 一条已知答不了的题

**X09（两版 618 方案对比）在降级模式下必然失败。** 降级路径是**抽取式**的：
它从检索到的句子/工具结果里摘内容拼回答，不做跨文档的综合归纳。
"商品从三文鱼poke 换成牛肉poke、价格从 25 变 29"这个结论要同时读两份文档再对比，
模板路径给不出来——它只会引用 KB-023，答不出 2025 那一半。

这是**降级路径的设计边界**，不是缺陷：那条路径的价值在于"不配 Key 也能答对大多数题，
且同样的输入给同样的输出"，而不是替代模型。配了 Key 之后这道题由模型作答。
留在这里是为了把这条边界写清楚，而不是把它藏起来。
